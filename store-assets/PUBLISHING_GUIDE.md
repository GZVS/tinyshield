# Chrome Web Store publishing guide — Zenith Guard 3.2.0

## 1. Finish local browser checks

Run the source tests and follow `docs/RELEASE_CHECKS.md`. Verify that `python tools/validate.py` passes and that the full category rules index and enable successfully.

## 2. Create or update the public source repository

Suggested name: **Zenith Guard**  
Suggested description: **High-performance ad, tracker, and security blocker for Chrome and Microsoft Edge with next-gen video ad skipping, extensive filtering, and ambient dark UI.**

Upload the source-folder contents, including the license and third-party notices. Do not upload browser profiles, npm dependencies or cache files. The README explains the extension folder and tests.

## 3. Host the privacy policy

Copy the supplied `privacy.md` to your privacy-policy repository (e.g. `extensions/zenith-guard/privacy.md` or GitHub Pages). Open that file's public URL while signed out, then copy its exact URL. The policy uses the support email: zsgeorgios@icloud.com.

## 4. Upload the extension ZIP

In your Chrome Web Store Developer Dashboard, create a new item or open your existing item and upload **dist/zenith-guard-v3.2.0-chrome.zip**. The ZIP has `manifest.json` at its root and contains runtime files only.

Review the item identity/signing behavior when updating an existing extension; migration applies to the same installed extension ID. No `.pem` private key is supplied or needed for a store dashboard upload.

## 5. Complete the listing

- Title: `listing/title.txt`.
- Short description: `listing/short-description.txt` (matches the manifest).
- Full description: `listing/full-description.txt`.
- Suggested category: choose the current dashboard category that best describes browser filtering/productivity.
- Language: English for the supplied listing and UI.
- Support email: zsgeorgios@icloud.com.
- Website/support profile: https://github.com/GZVS, or the verified repository URL after you create it.
- Privacy policy: exact public URL verified in step 3.

## 6. Upload images

| Asset | File/size |
| --- | --- |
| Store icon | `icons/icon128.png` — 128×128 |
| Small promo tile | `promotional/small-promo-440x280.png` — 440×280 |
| Optional marquee | `promotional/marquee-1400x560.png` — 1400×560 |
| Screenshots | Verified actual captures from the sibling browser-QA folder — 1280×800 each, generated by the local QA script |

`ui-previews/` contains five 3.0 style references at 1280×800; the added 3.1 test controls are not shown. Use them to compare layouts, not as proof that live blocking passed. Promo artwork and UI previews use opaque RGB output; icons retain PNG transparency. Editable promo SVGs are included, but upload PNG files to the store.

## 7. Complete privacy and permissions

Use `listing/single-purpose.txt`, `listing/permission-justifications.md` and `listing/privacy-disclosures.md` as implementation-grounded guidance. Align every dashboard answer with the submitted code and `privacy.md`. State that no remote executable code is used. Do not claim comprehensive malware protection, perfect adult-site coverage, guaranteed YouTube blocking or a locked parental-control feature.

## 8. Submit for review

Check the summary, optional website-access behavior and all URLs. Submit only after the local browser release checks pass. Store approval, fees and account verification are controlled by Google and are not completed by this package.
